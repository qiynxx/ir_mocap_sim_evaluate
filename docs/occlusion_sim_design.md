# 基于 3D 模型的遮挡仿真设计方案

## 1. 背景与动机

### 1.1 当前仿真的局限性

现有仿真平台将 LED 点视为**自由悬浮的 3D 点**，仅判断：

- 点是否在相机前方（深度 > 0）
- 点的投影是否在图像范围内

**不考虑 LED 所在的物理载体（曲面外壳）对视线的遮挡**。这导致：

| 问题 | 影响 |
|------|------|
| 曲面背面的 LED 仍然可见 | 仿真中可见 LED 数量始终偏多 |
| 无自遮挡效果 | 旋转到侧面时 LED 数量不变 |
| 评估结果过于乐观 | PnP 求解始终有充足匹配点，不反映真实精度下降 |

### 1.2 改进目标

导入由 `3D_model_generate_2D_array` 工具设计的**带凹槽 3D 模型 (STL)**，实现：

1. **视线遮挡检测** — LED 被曲面几何遮挡时从 IR 图像中消失
2. **背面剔除** — LED 所在表面背对相机时不可见
3. **3D 模型可视化** — 在上帝视角中渲染实际的曲面网格
4. **真实可见性统计** — 可见 LED 数量随姿态变化，反映真实场景

## 4. 技术方案

### 4.1 核心技术：射线-网格求交 (Ray-Mesh Intersection)

对每个 LED 点，从相机位置向 LED 方向发射一条射线，检测射线是否与 3D 模型网格相交。

**算法原理：**

给定射线起点 $O$（相机位置）和方向 $D$（归一化），射线上任意点为：

$$P(t) = O + t \cdot D, \quad t \geq 0$$

对网格的每个三角面片，使用 **Möller–Trumbore 算法** 计算射线与三角形的交点：

1. 设三角形三个顶点为 $V_0, V_1, V_2$，定义边向量：
   $$E_1 = V_1 - V_0, \quad E_2 = V_2 - V_0$$
2. 计算辅助向量：
   $$H = D \times E_2, \quad a = E_1 \cdot H$$
3. 若 $|a| < \epsilon$，射线与三角形平面平行，无交点
4. 否则计算重心坐标 $(u, v)$ 和距离 $t$：
   $$S = O - V_0, \quad u = \frac{S \cdot H}{a}, \quad Q = S \times E_1, \quad v = \frac{D \cdot Q}{a}, \quad t = \frac{E_2 \cdot Q}{a}$$
5. 若 $u \in [0,1]$, $v \in [0,1]$, $u+v \leq 1$, $t > 0$，则存在有效交点

**加速结构：** 直接遍历所有三角形的复杂度为 $O(N)$，使用 **BVH (Bounding Volume Hierarchy)** 空间索引加速到 $O(\log N)$。trimesh 内置的射线引擎（基于 embree 或 pyembree）已实现此加速。

**遮挡判定逻辑：**

```
对每个 LED:
  1. 构造射线: 起点 = 相机位置, 方向 = LED位置 - 相机位置
  2. 计算射线与网格所有三角面的交点
  3. 找到最近交点距离 d_hit
  4. 计算相机到 LED 的距离 d_led
  5. 若 d_hit < d_led - ε:  LED 被遮挡 → 不可见
     否则:                   LED 未被遮挡 → 可见
```

其中 $\epsilon$ 是一个小容差值（约 1~2mm），避免 LED 自身所在的面片误判为遮挡。

### 4.2 背面剔除 (Back-face Culling)

即使射线未被遮挡，如果 LED 所在表面的法线方向背对相机，现实中 LED 的光无法到达相机。

**判定方法：**

计算 LED 所在面片的法线 $\hat{n}$ 与视线方向 $\hat{v}$（从 LED 指向相机）的夹角：

$$\cos\theta = \hat{n} \cdot \hat{v}$$

- $\cos\theta > 0$：表面朝向相机 → LED 可见
- $\cos\theta \leq 0$：表面背对相机 → LED 不可见

**法线获取方式：** 找到距离 LED 最近的三角面片，使用该面片的法线。trimesh 提供 `mesh.face_normals` 和最近面查询 API。

### 4.3 LED 发射角衰减（可选增强）

真实 IR LED 的辐射强度随偏离法线的角度衰减，通常遵循 **朗伯余弦定律 (Lambert's Cosine Law)**：

$$I(\theta) = I_0 \cdot \cos\theta$$

当 $\theta > \theta_{max}$（LED 的半功率角，通常 ±60°）时，强度几乎为零。

在仿真中可以通过调节 IR 图像中亮斑的像素亮度来模拟此衰减。

### 4.4 3D 模型渲染

在上帝视角中使用 OpenGL 渲染 3D 网格，使 LED 板在视觉上不再是抽象的点和线。

**渲染方式选项：**

| 方式 | 效果 | 性能 |
|------|------|------|
| 线框模式 (GL_LINE) | 透明感好，能看到内部 LED | 极低开销 |
| 半透明实体 (alpha blend) | 有实体感，仍可透视 | 低开销 |
| 实体 + 光照 (GL_FILL + Lighting) | 最真实 | 中等开销 |

推荐使用**半透明实体**，兼顾真实感和 LED 可见性。

## 5. 使用的技术栈

| 技术 | 用途 | 说明 |
|------|------|------|
| **trimesh** | 3D 网格加载 + 射线求交 | 支持 STL/OBJ 等格式，内置 BVH 加速的 ray casting |
| **embree** (可选) | 高性能射线求交加速 | Intel 开源引擎，trimesh 可自动调用，性能提升 10-100x |
| **NumPy** | 向量/矩阵计算 | 法线计算、坐标变换、批量射线方向计算 |
| **OpenGL** | 3D 网格渲染 | 在现有 Pygame+OpenGL 框架上扩展，渲染三角面片 |
| **Pygame** | 窗口管理 + 输入处理 | 沿用现有框架 |
| **ZMQ** | 进程间通信 | 沿用现有架构，仿真图像发布 + 评估数据订阅 |

### trimesh 射线求交 API

```python
import trimesh

mesh = trimesh.load("model_with_grooves.stl")

ray_origins = np.array([[cam_x, cam_y, cam_z]])       # 相机位置
ray_directions = np.array([[dx, dy, dz]])              # 射线方向（归一化）

# 返回: 交点坐标, 射线索引, 面片索引
locations, index_ray, index_tri = mesh.ray.intersects_location(
    ray_origins=ray_origins,
    ray_directions=ray_directions
)
```

trimesh 在加载网格时自动构建 BVH，后续射线查询均为 $O(\log N)$ 复杂度。对于 11 个 LED × 2 个相机 = 22 次查询/帧，在万面级网格上可在 **< 1ms** 完成。

## 8. 预期收益

1. **精度评估更可靠** — 仿真结果可直接指导实际部署决策
2. **发现设计盲区** — 某些角度可见 LED 不足导致定位失败的场景
